MediReach UI Rewire Audit

What every control in UI/ does today, which layer the new Stitch-styled screens must plug into, and where the redesign would break behaviour if built carelessly. Nothing has been modified — this is the map I would work from.

Which app is being redesigned?

This audit covers UI/ (React Query + RTK, Tailwind 4) — the newer of the two live frontends. Frontend/ is a separate parallel app that still receives commits and holds the video call, chatbot and forgot-password screens. I assumed UI/; say the word if you meant both.

New folder, or in place?

“new_UI” reads as a new sibling directory. A copy diverges from UI/ the moment someone commits to either. Redesigning inside UI/ on a branch keeps one source of truth — my recommendation unless you want the old UI running side by side.

03

Reuse layer — do not touch

Every one of these is already the shared seam between UI and behaviour. The redesign imports them exactly as the current components do; no handler gets rewritten, no endpoint gets re-called from a new place.

API surface

src/api/backend.js · axiosInstance.js

All 30+ endpoint functions plus the bearer-token interceptor. New components import the same functions.

Query hooks

hooks/useStats · UseAllDcotors · UseAllDepartment · Usedoctordashboard · useTodaysAppointments · useConfirmAppointment

Including the optimistic confirm mutation and its rollback — reused as-is, keys unchanged.

Redux slices

redux/slices/{auth,opd,notification,theme}.js · redux/store.js

The OPD slice is the queue's single source of truth. New controls dispatch the same actions.

Socket client

src/socket.js

Manual connect after login, token from localStorage, joinDoctor emit, new-appointment listener.

Route guards

Routes/protectedRoutes.jsx · PublicRoute.jsx · constants/Role.js

Role gating and redirect targets stay byte-identical; only what renders inside changes.

Container logic

DoctorHome.jsx handlers · DoctorDashboard.jsx status gate

The promote-or-end branches move with the component, not rewritten — new presentational children receive the same props.

06

Risks

Ordered by what would actually cost you a working feature.

The Stitch screens show data the API does not return high

The appointment roster renders MRN, chief complaint, live vitals (BP, HR, SpO₂), avg wait and slot times. GET /appointments/today returns only { token, appointmentId, patient(name/email/gender), status, bookedAt }. Copying the design literally means inventing fields or shipping empty columns.

Plan: keep the Stitch layout and typography, drop columns with no backing data, and tell you which ones I removed rather than filling them with placeholders.

The OPD state machine is easy to break from the view layer high

The backend enforces one CURRENT appointment per doctor per day and refuses to stop OPD while a consultation runs. The current buttons are conditionally rendered so the impossible transitions cannot be triggered. A redesign that shows all controls at once (as a toolbar-style layout invites) would start producing 409s and “OPD not started” errors.

Plan: carry the exact render conditions over — Start Consultation only when started && !paused && no current; Pause only with a current; Resume only when paused.

Two socket clients, two conventions medium

DoctorStatus builds its own io() connection instead of the shared socket.js. Consolidating them during a visual pass looks tidy and would silently change connection lifetime and listener cleanup.

Plan: leave both as they are. Refactor separately if you want it.

Existing bugs that a rewrite would “accidentally” fix medium

Login switches on ROLE.hospital_admin, which is undefined — admins fall through to navigate("/") and only land on their dashboard because PublicRoute catches them. /signup/pharmacy renders a placeholder while the real form sits unrouted. The pharmacy index route renders a second sidebar. Silently repairing these changes behaviour you did not ask me to change.

Plan: preserve as-is by default; list them for you to green-light individually.

Hardcoded localhost and hand-rolled requests medium

OpdSchedule, DoctorStatus, AddMedicine and SignupPharmacy call http://localhost:3000 through raw axios with a manually attached token instead of axiosInstance. Moving them to the shared instance during the redesign would change header and error behaviour.

Plan: leave the call sites alone; only the markup around them changes.

Dark mode is a class on <html> low

index.css defines @custom-variant dark (&:where(.dark, .dark *)) and useThemeSync toggles that class. Several components hardcode dark-only colors (bg-slate-900, bg-[#111827]) and are unreadable in light mode already.

Plan: the token pass fixes this as a side effect — both themes get designed, which is a visual change, not a behavioural one.

No tests, no safety net low

There is nothing to run that would catch a broken handler wire-up. Verification is manual.

Plan: redesign screen by screen, keeping each commit small enough to eyeball against this inventory.
